# Loop: autopi-ha
tier: routine
gate: just check
ci-required: ci-success
grafana-stack: none

Public repository carrying real vehicle data: no token, device UUID, vehicle id, VIN, plate, GPS
coordinate or email in any tracked file or loop artifact (`AGENTS.md` has the sweep). `just check`
is `fmt-check lint typecheck test`; CI also runs hassfest and HACS validation, which have no local
recipe. A lane touching `manifest.json`, `hacs.json` or the integration layout says its proof is
partial instead of claiming a full gate. Always `uv run`, never a bare `python` or `pytest`.

## Credentials

- The real AutoPi API token is never in the repo and a lane never authenticates. Lanes work from
  fixtures under `tests/`; a lane needing a new sample asks the one live-API caller, which redacts
  to shapes (`<device-uuid>`, `<vehicle-id>`) before anything leaves it.

## Traps

- The AutoPi API returns no unit for any data field, so a sensor scaling is a standing inference.
  Put it behind a named constant, state its provenance and failure mode in the docstring and pin
  it with a test. With no evidence, register raw passthrough: no unit, device class or state class.
- Declare the unit in `__init__` and convert in `native_value`; never override
  `native_unit_of_measurement` (the property wins and the attribute contradicts it).
  `TripOdometerSensor` is the shape to copy.
- Check a `device_class`/`state_class` pair against the pinned Home Assistant package, not memory:
  `energy` takes `total`/`total_increasing`, `energy_storage` takes `measurement`.
- An unreported field produces no entity, so the bar for registering one is evidence about its
  unit, not whether some vehicle has it. Contributor-reported fields arrive with no units.
- `docs/entities.md` is generated by `just docgen` and no CI step checks it: a sensor change that
  skips it ships stale published docs.
- Defects here are units-and-classes bugs that pass the gate; look at sensor metadata first in
  review. `coordinator.py`, `data_field_sensors.py`, `sensor.py`, `client.py` and `types.py` are
  the large files.

## Mutexes

- The live AutoPi account: at most one lane makes live API calls, and the brief names it.
- Wiring-only, edited by one pass and never by a feature lane: `FIELD_ID_TO_SENSOR_CLASS`
  (`data_field_sensors.py`), `POSITION_FIELD_TO_SENSOR_CLASS` (`position_sensors.py`),
  `AUTO_ZERO_METRICS` (`auto_zero.py`), `PLATFORMS` (`const.py`), `docs/entities.md`,
  `manifest.json` and `hacs.json`. A lane writes its sensor class and stops at the registry; it
  records the registry row it needs in its return.

## Lane brief

Stay out of the wiring-only files above. A change needed outside your map goes in your return,
exactly, and you finish the rest of your scope.
